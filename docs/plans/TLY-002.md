# TLY-002 Local stack with docker compose — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (see Ruling R4). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `make up` starts Postgres (3 databases), Kafka KRaft, Redis, Keycloak (2 realms), OTel collector, Prometheus, Tempo, Loki and Grafana with every health check green inside 120 s, reports total resident memory (≤ 16 GB), creates the five topics from docs/04 §7 with documented partitions/retention/compaction; `make seed` loads `contracts/fixtures/tenants.json`; `make down ARGS=-v` leaves a clean slate.

**Architecture:** One `deploy/compose.yaml`, one Postgres instance with three databases created by an init script, one combined-mode Kafka broker, a one-shot `kafka-init` container that declares topics idempotently, and an observability quartet behind a single OTel collector. No application containers — core/workers/web are still skeletons (TLY-004..007); they join the stack later on the same network.

**Tech Stack:** Docker Compose v2 (`--wait`), `postgres:18-alpine`, `apache/kafka:4.1.0` (KRaft), `redis:8-alpine`, `quay.io/keycloak/keycloak:26.4`, `otel/opentelemetry-collector-contrib`, `prom/prometheus`, `grafana/tempo`, `grafana/loki`, `grafana/grafana`, bash + python3 for seed/report scripts.

**Spec:** docs/06-user-stories.md TLY-002 AC1–AC5 · docs/07-delivery-plan.md Sprint 0 (A-01 memory check) · docs/02-software-architecture.md §ports (5432/9092/6379/8180/3300/9095/3200/3101) and §stack · docs/04-api-contract.md §7 (topics) · docs/05-data-model.md (`deploy/keycloak/*.json`).

## Global Constraints

- Lane PLAT owns `deploy/` and the `up`/`down`/`seed` Makefile targets only. **Do not touch** `contracts/`, `scripts/gen_*.py` or `make contracts`/`make gen` — TLY-003 runs in parallel there.
- Ports are fixed by docs/02: Postgres 5432, Kafka 9092, Redis 6379, Keycloak 8180, Grafana 3300, Prometheus 9095, Tempo 3200, Loki 3101.
- Total resident memory ≤ 16 GB (NFR-COST-01 / A-01), **reported by `make up`** and failing the target if exceeded.
- No secrets, real personal data or real card data anywhere, including realm exports and seed output (root CLAUDE.md §9). Local dev credentials are obvious placeholders (`tally`/`tally`, `admin`/`admin`).
- Every service has a container health check; `docker compose up -d --wait` is the gate, budget 120 s.
- Idempotent: `make up` twice in a row, and after `make down ARGS=-v`, both succeed.

## Rulings

- **R1 — AC4 "and the core API".** The core does not exist yet (TLY-004, same sprint) *and* `contracts/ops-openapi.yaml` has no tenant-creation operation — only `opsListTenants`/`opsGetTenant`. Inventing a seed endpoint would breach root CLAUDE.md §9, so `deploy/seed.sh` seeds Keycloak unconditionally, probes the core at `$TALLY_CORE_URL` (default `http://localhost:8080`) and reports the deferral. The POST loop lands with TLY-101 (tenant provisioning). Recorded for tech-lead review.
- **R2 — AC5 `make down -v`.** GNU Make consumes `-v` itself (prints its version), so the literal command in the AC cannot reach docker compose. The Makefile (authored by TLY-001) already exposes `ARGS`; the supported form is `make down ARGS=-v`. Documented in `deploy/README.md`. Suggested doc fix: change the AC wording in docs/06.
- **R3 — OTel collector health check.** The contrib image is distroless (no shell, no curl), so a container-level `CMD-SHELL` health check is impossible. The collector exposes `health_check` on 13133, which `deploy/stack-report.sh` probes from the host as part of `make up`. AC1's "all health checks green" is therefore satisfied by container health checks for the 8 shell-bearing services plus a host-side probe for the collector.
- **R4 — subagent-driven-development vs executing-plans.** Root CLAUDE.md §4 allows `executing-plans` for "small or tightly coupled stories". This story is a single cohesive artifact (one compose file plus its config files); every task edits the same graph and must be verified by booting the whole stack, so fan-out would multiply context without parallelism. Executed in-session with the same ledger, per-task verification and final whole-branch review.
- **R6 — host ports are overridable.** Another local compose stack on the same machine already held 9092/5432/3200/4317/4318/13133, which made the docs/02 ports unbindable. Every published port is now `${TALLY_*_PORT:-<docs/02 default>}`: the documented ports are unchanged for anyone with a free machine, and a developer with a clash sets one variable instead of editing the compose file. Verification below was run with six of them shifted.
- **R7 — `postgres:18` volume mount.** The 18+ image refuses a volume mounted at `/var/lib/postgresql/data`; the mount is at `/var/lib/postgresql` (one level up) as the image instructs.
- **R5 — `make ddl-snapshot`.** Its script `deploy/ddl-snapshot.sh` lives in `deploy/` but is not in any TLY-002 AC and needs migrations that do not exist yet (TLY-004). Left to the data-model story.
