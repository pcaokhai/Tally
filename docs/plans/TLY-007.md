# TLY-007 — Operator console shell

Lane OPSW · 3 pts · Depends TLY-001, TLY-003 · Traces NFR-ADM-UX-02, NFR-ADM-SEC-09
Branch: `feat/TLY-007-operator-console-shell`

## 1. Understanding

Build the real Next.js operator console shell in `ops-web/`, replacing the TLY-001
placeholder `src/index.ts`. Per docs/06 TLY-007 the shell needs: a separate app on port
3100 with a dark compact theme and the 14-item ops sidebar (AC1); a non-dismissible
environment badge (PRODUCTION red / STAGING amber) and a session timer on every page
(AC2); a strict CSP with `frame-ancestors 'none'` and no third-party scripts, verified by
a Playwright header check (AC3); and mock mode driven by the MSW handlers generated from
`contracts/ops-openapi.yaml` (AC4). `ops-web/CLAUDE.md` fixes the layout
(`app/(console)/layout.tsx` = badge + timer + sidebar) and the visual rules (dark-first,
compact 32–40 px rows, mono for ids and amounts, motion only for live data / state
changes). docs/02 §"NFR-ADM-SEC-01..09" gives 15 min idle / 8 h absolute session bounds
and VPN-only; docs/02 §deployables fixes port 3100. docs/10 §4.4 fixes the TypeScript /
React rules (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, no
`any`, server components by default, Tailwind tokens only, reduced-motion variants,
accessibility part of done). No tenant or customer data appears anywhere: every value in
the shell is a static stub.

## 2. Rulings

- **R1 — the design canvas is not in the repo.** docs/06 TLY-007 says "the 14-item ops
  sidebar from the canvas" and names artboard `Admin Overview (shell)`; the canvas is an
  external link (docs/01 §7.1) and no artboard export exists under `docs/assets/`. The
  authoritative in-repo list is `ops-web/CLAUDE.md` §Layout, which names exactly 14
  routes: overview, tenants, health, fleet, jobs, recon, refunds, ledger, plans, flags,
  approvals, impersonation, audit, operators. **Resolved:** take those 14 as the sidebar,
  single-sourced in `lib/nav.ts`. Count is asserted by a test so a later canvas import
  that disagrees fails loudly.
- **R2 — session timer without an auth story.** Operator auth (WebAuthn, operator realm)
  belongs to TLY-801/TLY-802, not TLY-007. AC2 only requires the timer to *render on
  every page*. **Resolved:** the shell renders a real idle/absolute countdown over the
  docs/02 NFR-ADM-SEC-01 bounds (15 min idle, 8 h absolute) computed by a pure,
  unit-tested function, seeded from a stub session start. Wiring it to a real session is
  left to TLY-802, marked with a `TODO(TLY-802)`.
- **R3 — 14 routes, 2 page files.** Creating 14 near-identical placeholder route folders
  is scaffolding for later stories (TLY-803/805/... own them). **Resolved:** overview is
  `app/(console)/page.tsx`; the other 13 are served by one dynamic
  `app/(console)/[section]/page.tsx` that validates the slug against `lib/nav.ts` and
  `notFound()`s otherwise. Later stories replace a section by adding its static folder,
  which takes precedence over the dynamic segment.
- **R4 — Tailwind.** docs/10 §4.4 says "Tailwind tokens only". Tailwind v4 is added with
  the console's own `@theme` token block in `app/globals.css`; no config file, no plugin,
  no component library. Tokens are deliberately *not* shared with `web/` yet (that is a
  `components/ui/` concern for a later slice) so the two apps stay visually distinct.
- **R5 — `make lint` expects `pnpm lint && pnpm typecheck` to cover the app.** The
  TLY-001 `lint` script is `eslint src --ext .ts`. It is widened to the real source roots
  and `.tsx`; the script *names* (`lint`, `typecheck`, `test`, `gen`) are unchanged.

### Rulings made during execution

- **R6 — plan tasks T2 and T3 merged into one implementer.** Both write
  `app/(console)/layout.tsx`; splitting them across serial agents in a shared worktree
  buys nothing and risks a conflict on the same file.
- **R7 — three deviations accepted in the shell work.** (a) RTL `cleanup()` added to
  `vitest.setup.ts` — without it DOM leaked between tests in the same file; (b) the
  session timer's `aria-live` is split: `off` on the ticking digits (announcing every
  second is unusable) and a separate polite `sr-only` region that only has text under the
  2-minute threshold; (c) `EnvironmentBadge` takes an optional `env` prop defaulting to
  the parsed singleton, so each environment is testable without `vi.resetModules()`.
- **R8 — AC3 is not met by a header assertion alone.** The first CSP implementation
  shipped `script-src 'self'` on the claim that Next 16 emits no inline bootstrap script.
  That claim was false: the built HTML carries two inline `<script>` tags (the App Router
  RSC payload), which the policy blocked, so nothing hydrated — a console that looked
  correct and was dead. The header-only e2e check could not see it because it inspected
  `script[src]` only. AC3 therefore also requires a hydration test under the real policy
  (`e2e/csp.spec.ts` asserts zero CSP violations and that the timer's `mm:ss` changes
  between two observations).
- **R9 — `make e2e` now also runs the ops-web Playwright suite.** `Makefile` is PLAT's
  lane (root CLAUDE.md §5), so this was raised rather than taken. The tech lead approved
  OPSW making the one-line change inside this story, on the TLY-002/TLY-003 precedent that
  a lane may touch the root Makefile when the change is a direct, low-risk consequence of
  what the story built. Without it, AC3's "verified by a Playwright header check" would
  hold only when a human remembered to run it.
- **R10 — the nonce CSP trades static rendering for a policy that works.** A per-request
  nonce can only be stamped during per-request SSR, so the 16 routes moved from
  prerendered to server-rendered on demand. Next documents nonces and static
  optimisation as mutually exclusive, and `rules/web/security.md` mandates a nonce over
  `'unsafe-inline'`. ops-web is a VPN-only console with no anonymous users and no SEO
  need, so the cost (no CDN-cached shell HTML) is accepted rather than weakening the CSP.
- **R11 — the console shell must be server-rendered, and rendered exactly once.**
  Verification after the CSP fix found two defects that every preceding report had missed:
  `MockProvider` withheld its children until the MSW worker started, so every page served
  an empty `<body>` (the non-dismissible badge existed only after JS, and `notFound()`
  answered 200 because the empty shell had already flushed); and a `notFound()` thrown
  inside `(console)` rendered the root `not-found.tsx` *nested in* the console layout,
  producing two badges and two sidebars. Both are now asserted in the browser, not by unit
  tests that render components outside the route tree — which is how they hid.

- **R12 — this PR exceeds the 400-line budget, deliberately.** Excluding generated code
  (`ops-web/lib/api/generated/**`, untouched), `public/mockServiceWorker.js` and
  `pnpm-lock.yaml`, the diff is ~1400 changed lines. Root CLAUDE.md §14 caps a story at
  400. The overage is almost entirely the one-off cost of standing up a new lane's
  application: tsconfig, eslint flat config, vitest and Playwright config, the PostCSS and
  Tailwind token layer, the proxy, and ~15 test files. Application logic is a small
  fraction of it. The 400-line budget is sized for stories inside an existing app, not for
  "create the app". Recorded here rather than left for a reviewer to discover; subsequent
  OPSW stories build inside this shell and are expected to fit the normal budget.
- **R13 — AC4 is proven in a real browser, not only node-side.** The final review
  correctly noted that `setupServer` tests prove the handler set but not that the MSW
  service worker registers and intercepts under the strict CSP. `e2e/mock-mode.spec.ts`
  now drives a real tab: it polls a client-side `fetch('/ops/v1/overview')` until the
  worker answers 200 and asserts that registering the worker raises no CSP violation.

## 4. Design direction (so it is not a template, and not `web/`)

Instrument panel, not product UI. Near-black `oklch(14%)` canvas, 1px hairline rules
instead of cards, 2px radii, `ui-monospace` for every id/number/duration, uppercase
micro-labels at 10px with wide tracking, one signal accent (cyan) reserved for focus and
the active row, semantic color only for state. Sidebar rows 30px with a left activity
bar; the environment badge is a full-width hazard strip across the top, not a pill.
No gradients, no shadows, no illustrations, no count-ups.
