# TLY-004 — Core skeleton: Java 25, Spring Boot 4, Spring Modulith

Lane CORE · 5 pts · Branch `feat/TLY-004-core-skeleton` · Spec: `docs/06-user-stories.md` §TLY-004 (AC1–AC5)

## Understanding

TLY-001 left `core/` as a plain-Java Gradle skeleton; TLY-003 bolted on `openApiGenerate`
plus **placeholder** Spring/Jakarta/Jackson pins and a sample `IdentityController`, explicitly
marked `// TLY-004 replaces these individually pinned deps with the Spring Boot BOM`.
This story replaces that placeholder wholesale with the real Spring Boot 4 platform, creates the
eleven Spring Modulith module packages from `core/CLAUDE.md`, makes `archTest`, `integrationTest`,
`spotlessCheck` and `spotlessApply` real tasks, adds the Flyway baseline and a Testcontainers
integration base class, splits the three ports, emits JSON logs, and turns the OpenAPI
request/response validator on in tests.

Nothing outside `core/` and `docs/` is touched. `contracts/`, `deploy/`, `workers/`, `web/`,
`ops-web/` belong to other lanes.

   - Spring Modulith BOM `2.1.1`
   - ArchUnit **core** `1.5.0` (`com.tngtech.archunit:archunit`)
   - Spotless Gradle plugin `8.10.2`
   - `com.atlassian.oai:swagger-request-validator-spring-webmvc` `3.0.0`
   - openapi-generator plugin `7.14.0` (unchanged, already pinned)
   - Boot-managed, do **not** re-pin: Testcontainers 2.0.5, Flyway 12.4.0,

## Rulings (made at planning time, before dispatch)

- **R1 — `GET /v1/health` does not exist in `contracts/openapi.yaml`.** AC4 says "`GET /v1/health`
  *style* probes". Root `CLAUDE.md` §9 forbids adding endpoints outside the contract in a feature
  branch. **Ruling:** health probes are served by Spring Boot Actuator on the management port
  **8082** (`/actuator/health`, `/actuator/health/liveness`, `/actuator/health/readiness`); 8080
  and 8081 serve only their contracted API prefixes and are proven live by tests. No uncontracted
  `/v1/health` handler is added. *Cost if wrong:* a one-line contract PR plus a trivial controller
  in a follow-up.
- **R2 — ArchUnit engine.** Spring Boot 4.1 manages JUnit Jupiter **6.0.3**; `archunit-junit5`
  targets Jupiter 5 and its `@AnalyzeClasses` engine may not load. **Ruling:** use ArchUnit
  **core** (`com.tngtech.archunit:archunit:1.5.0`) with `ClassFileImporter` inside plain JUnit
  tests. *Cost if wrong:* none — this is the lower-magic option either way.
- **R3 — "a deliberate violation in a test fixture fails the build" (AC2).** Taken literally this
  means shipping a permanently red build. **Ruling:** ship a test-source fixture package
  `com.tally.core.archfixtures` containing one deliberate violation per rule, and a self-test
  (`ArchRulesBiteTest`) asserting each rule **reports** a violation against that package. The
  production rule runs exclude `..archfixtures..`. This proves the rules bite while keeping CI
  green. *Cost if wrong:* rename/restructure of one test class.
- **R4 — Flyway number.** `docs/05` §5 reserves `V100–V199` for E1 onward; the story names
  `V001__baseline_roles_schemas.sql`. **Ruling:** `V001` is the pre-epic baseline and is reserved
  here for TLY-004; epic migrations still start at V100. Content is the header block of
  `docs/assets/ddl/tally-baseline.sql` only (pgcrypto, roles `tally_app`/`tally_readonly`,
  the 11 schemas, `kernel.current_tenant()`); tables/RLS policies belong to V100+.
  *Cost if wrong:* renumber one file before any other migration exists.
- **R5 — the generated `com.tally.core.api` package would look like a 12th Modulith module.**
  **Ruling:** (a) move `IdentityController` to
  `com.tally.core.tenancy.adapter.in.web.IdentityController`; (b) exclude `com.tally.core.api..`
  from `ApplicationModules.of(...)` via an exclusion filter, since it is generated contract code,
  not a bounded context. *Cost if wrong:* adjust one predicate.
- **R6 — Spring Security is not introduced in this story.** ADR-022 requires `/ops/v1` to have its
  own `SecurityFilterChain`, but real authentication is TLY-103/TLY-102 and `contracts/ops-openapi.yaml`
  interfaces are not even generated yet. **Ruling:** port separation is enforced now by a small
  `PortScopeFilter` in `kernel` (404 for `/ops/v1/**` off port 8081 and `/v1/**` off port 8080);
  TLY-103 replaces it with the two real `SecurityFilterChain` beans. *Cost if wrong:* the filter
  is deleted when the chains land.
- **R7 — tracing.** Full OpenTelemetry wiring is TLY-901 (ADR-018). **Ruling:** a `RequestContextFilter`
  in `kernel` populates MDC `request_id`, `trace_id` and `span_id` from an inbound W3C `traceparent`
  header, generating them when absent. No micrometer-tracing / OTel dependency is added here.
  *Cost if wrong:* the filter is replaced by the OTel bridge in TLY-901.
- **R8 — JSON logging.** Rather than adding `logstash-logback-encoder`, use Spring Boot's built-in
  structured logging (`logging.structured.format.console=<class>`) with a ~40-line
  `TallyStructuredLogFormatter` emitting exactly the `docs/02` §7.6 field set. No new dependency.
  *Cost if wrong:* swap the formatter for an encoder dependency.
- **R9 — no JaCoCo / coverage gate in this story.** `docs/08` §3 sets ≥80 % line coverage as a
  *merge* gate, but a skeleton has almost no business logic and an enforced threshold here would
  gate on framework wiring. **Ruling:** coverage tooling lands with the first business module
  (TLY-101/102). *Cost if wrong:* one `jacoco` block added later. Recorded so it is not forgotten.
- **R10 — Spotless formatter.** `palantir-java-format` is the documented choice (`docs/10` §4.1)
  but may not yet support JDK 25. **Ruling:** try `palantirJavaFormat()` first; if it fails under
  JDK 25, fall back to Spotless' `importOrder`/`removeUnusedImports`/`trimTrailingWhitespace`/
  `endWithNewline` and record the fallback in the ledger. Generated sources are always excluded.
  *Cost if wrong:* a formatter swap, no semantic change.
- **R11 — log masking helpers** are named for TLY-004 by `docs/09` R-11. **Ruling:** ship a minimal
  `kernel.logging.Mask` (email + secret/token masking) with unit tests, nothing more.
- **R12 — unit vs integration split.** One source set, JUnit tag `integration`:
  `test` excludes it, `integrationTest` includes only it. Fewest files, keeps `make test` working.
