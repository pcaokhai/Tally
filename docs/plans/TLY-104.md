# TLY-104 — BFF login, session and tenant switcher

Track B (auth/session — full ceremony). Lane WEB. Branch `feat/TLY-104-bff-login-tenant-switcher`.

## Ruling: route group naming

`web/CLAUDE.md`'s layout diagram lists `app/(auth)/` for login/callback/switch-tenant, implying
a `/auth/*` URL prefix. Next.js route groups `(name)` are excluded from the URL path — a route
under `app/(auth)/login/route.ts` serves at `/login`, not `/auth/login`. Confirmed by manually
probing a throwaway route group during dev-server verification. Kept the `(auth)` folder (it's
still useful for grouping these three routes away from `(app)`'s layout) but the routes serve at
`/login`, `/callback`, `/switch-tenant`. No contract/doc change needed — this is web-internal
routing, not an OpenAPI path. Recording here per CLAUDE.md's precedence/ruling requirement since
it deviates from the literal (if ambiguous) layout comment in `web/CLAUDE.md`.

## Ruling: Next 16 proxy rename

This Next.js version renamed the `middleware.ts` convention to `proxy.ts` (function export
`proxy`, no `runtime` config — proxy always runs on Node.js). Used `proxy.ts` accordingly;
confirmed via `node_modules/next/dist/docs` and the dev server's own deprecation warning.

## Approach

- `lib/session.ts` — AES-256-GCM encrypted session cookie via `node:crypto` (stdlib, no new
  dependency for this). Payload: userId, tenantId, memberships, issuedAt, lastSeenAt.
  `sessionState()` computes idle (30 min) / absolute (12h) expiry.
- `app/(auth)/login/route.ts` (serves `/login`) — starts the Keycloak Authorization Code flow;
  mock-mode short-circuit (no `KEYCLOAK_ISSUER_URL`) goes straight to `/callback` with a fake
  code, since TLY-102/103's live IdP isn't up yet (frontend never waits).
- `app/(auth)/callback/route.ts` (serves `/callback`) — exchanges the code for identity (mocked
  for now, same Identity shape the real exchange will fill), sets the encrypted httpOnly/
  Secure(prod)/SameSite=Lax cookie, redirects to `target`.
- `app/(auth)/switch-tenant/route.ts` (serves `/switch-tenant`) — verifies the requested tenant
  is in the caller's own memberships, reissues the cookie scoped to that tenant.
- `proxy.ts` — gates every non-public route on session validity; idle/absolute-expired or
  missing/tampered cookie redirects to `/login?target=<original path>`, clearing the cookie.
- `lib/queryClient.ts` + `components/QueryProvider.tsx` — TanStack Query wiring (added as a
  dependency; required by `web/CLAUDE.md`'s "TanStack Query for client data" rule, wasn't
  installed yet).
- `components/shell/TenantSwitcher.tsx` — reads `GET /v1/me` (MSW fixture: two tenants, AC5),
  renders a `<select>` of memberships, on change POSTs `/switch-tenant`, calls
  `queryClient.clear()` (NFR-SEC-01 / AC3), then a hard `window.location.reload()` so first
  render of the new tenant starts from a genuinely clean module/browser state, not just an
  empty query cache.
- `mocks/handlers.ts` — added a fixture override for `GET /v1/me` returning two tenants.

## Manual verification (dev server, mock mode)

```
SESSION_SECRET=dev-secret-please-rotate npx next dev -p 4173
curl -i http://localhost:4173/                                  # 307 -> /login (no session)
curl -i "http://localhost:4173/login?target=%2F"                # 307 -> /callback?code=mock-auth-code
curl -i -c cookies.txt "http://localhost:4173/callback?code=mock-auth-code&target=%2F"
                                                                  # 307 -> /, sets httpOnly/SameSite=lax
                                                                  # encrypted cookie (opaque, no plaintext ids)
curl -i -b cookies.txt http://localhost:4173/                    # 200 with cookie
curl -i -b cookies.txt -X POST -d '{"tenantId":"tenant_b"}' \
  http://localhost:4173/switch-tenant                            # 200, reissues cookie for tenant_b
curl -i -b cookies.txt -X POST -d '{"tenantId":"tenant_z"}' \
  http://localhost:4173/switch-tenant                            # 403 not a member
curl -i -X POST -d '{"tenantId":"tenant_b"}' \
  http://localhost:4173/switch-tenant                            # 307 -> /login (no session)
curl -i -b "tally_session=garbage.garbage.garbage" http://localhost:4173/
                                                                  # 307 -> /login, cookie cleared
```

All observed as expected; see session handback for pasted output.
