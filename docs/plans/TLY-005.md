# TLY-005 — Workers skeleton: Go 1.27 dispatcher and aggregator

**Spec:** `docs/06-user-stories.md` → "TLY-005 Workers skeleton: Go 1.27 dispatcher and aggregator" (Lane WORK, 3 pts, depends TLY-001 + TLY-003, traces NFR-MNT-01).
**Supporting:** `workers/CLAUDE.md` (layout, Go 1.27 rules, linter list), `docs/02-software-architecture.md` §7.6 (log fields, metric prefix, W3C traceparent) and §7.7 (typed config from env, validated at startup), root `CLAUDE.md` §6 rules 9/11/12.
**Branch:** `worktree-agent-a6065334bd8942e23` (worktree-isolated agent branch; integration handled by the coordinating session).

## Acceptance criteria (verbatim from docs/06)

1. `go build ./...` builds `cmd/dispatcher` and `cmd/aggregator` with `go 1.27` in go.mod; golangci-lint config from workers/CLAUDE.md passes.
2. Both binaries load typed env config and exit non-zero with a clear message when a required variable is missing.
3. SIGTERM stops intake and exits within 30 s; a `goleak` test proves no goroutine outlives shutdown.
4. depguard forbids `internal/*/domain`-style packages from importing pgx, franz-go or net/http; a violating import fails lint.

## Understanding

TLY-001 left two `main()` bodies printing placeholder strings. TLY-003 added `internal/events/` (generated, read-only) and `internal/store/` (guarded sqlc `go:generate` that intentionally skips until dispatcher migrations exist). This story replaces the two placeholders with the three things every later WORK story assumes: typed env config that fails fast, OTel + slog telemetry, and a shutdown path that stops intake and proves no goroutine outlives it. It also brings `.golangci.yml` up to the linter set `workers/CLAUDE.md` already documents, including the depguard rule of AC4. No Kafka/Postgres/Redis clients are wired — those arrive with TLY-304/TLY-305 and the aggregator stories. Nothing outside `workers/` and `docs/plans/` is touched.

## Rulings (pre-execution)

- **R1 — env var names are unspecified.** No doc fixes worker env var names. Chosen: OTel spec names for telemetry (`OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_SERVICE_NAME`), plain uppercase names for the rest (`LOG_LEVEL`, `SHUTDOWN_TIMEOUT`, `KAFKA_BROKERS`, `DATABASE_URL`, `REDIS_URL`). Cost if wrong: a rename in `internal/config` plus the compose service PLAT adds later.
- **R2 — "required variable" set.** A variable is required iff it has no sensible default. Required: dispatcher `DATABASE_URL`, `REDIS_URL`, `KAFKA_BROKERS`; aggregator `KAFKA_BROKERS`. Defaulted: `LOG_LEVEL=info`, `SHUTDOWN_TIMEOUT=30s`, `OTEL_SERVICE_NAME=<binary>`, `OTEL_EXPORTER_OTLP_ENDPOINT` empty ⇒ telemetry exports nothing (local `go run` must not require a collector). Cost if wrong: one line per field.
- **R3 — no `domain` package exists yet in `workers/`.** AC4's rule is written for a path shape that later stories create. The rule is configured now against `internal/*/domain/**` and proven by a permanent fixture package `internal/example/domain` guarded by build tag `depguardfixture`, so the violating file is excluded from normal builds and lint but can be linted on demand by the AC4 test. Cost if wrong: delete the fixture and prove AC4 with a throwaway temp file instead.
- **R4 — intake is a placeholder.** Neither binary has real intake yet (Kafka consumer = TLY-304). Both run an `intake` func that blocks on `ctx.Done()`; AC3 is proven against the shared `internal/app.Run` that both mains use, not against a fake consumer. Cost if wrong: nothing — TLY-304 swaps the func body.
- **R5 — OTLP exporter transport.** HTTP (`otlptracehttp` / `otlpmetrichttp`) over gRPC: fewer deps, collector exposes 4318. Cost if wrong: swap two constructors.

2. **GREEN.** `run.go`:
   ```go
   // Run executes intake until ctx is cancelled, then gives it shutdownTimeout
   // to return. ponytail: no supervisor tree — one intake func per binary is all
   // TLY-304/TLY-4xx need; add one when a binary genuinely runs two intakes.
   func Run(ctx context.Context, shutdownTimeout time.Duration, intake func(context.Context) error) error
   ```

### Task 5 — Wire both mains

Files: `workers/cmd/dispatcher/main.go`, `workers/cmd/aggregator/main.go`, `workers/cmd/dispatcher/main_test.go` (replaced).

1. Both mains become:
   ```go
   func main() {
       if err := run(); err != nil {
           fmt.Fprintf(os.Stderr, "dispatcher: %v\n", err)
           os.Exit(1)
       }
   }

   func run() error {
       cfg, err := config.LoadDispatcher()
       if err != nil { return err }
       ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)
       defer stop()
       shutdownTelemetry, err := telemetry.Setup(ctx, telemetry.Options{...})
       if err != nil { return err }
       defer func() { … shutdownTelemetry(context.WithoutCancel-ish bounded ctx) … }()
       slog.InfoContext(ctx, "dispatcher starting", "service", cfg.ServiceName)
       return app.Run(ctx, cfg.ShutdownTimeout, intake)
   }

   // intake blocks until ctx is cancelled.
   // ponytail: the Kafka consumer lands in TLY-304; this is the seam it plugs into.
   func intake(ctx context.Context) error { <-ctx.Done(); return nil }
   ```
   Aggregator identical with `LoadAggregator` and its own name/messages.
