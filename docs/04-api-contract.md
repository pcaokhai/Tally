# API Contract

Version 1.0 · 2026-09-22 · Owner: Tech lead · Normative source: `contracts/openapi.yaml`, `contracts/ops-openapi.yaml`, `contracts/events/`

`contracts/` wins over this document. Both OpenAPI files are generated by `scripts/gen_openapi.py`; add endpoints there.

## 1. Topology

| Prefix | Served by | Consumers |
| --- | --- | --- |
| `https://api.tally.example/v1/*` | core :8080 | tenant backends (API keys), web BFF (JWT) |
| `/v1/webhook_deliveries*`, `/v1/webhook_endpoints/health`, `/v1/streams/webhook_deliveries` | core `events` module proxying dispatcher internal API :9090 (ADR-031) | web |
| `https://ops.internal/ops/v1/*` | core :8081, operator realm | ops-web only |

BFF routes (not in OpenAPI; Next.js): `GET /auth/login`, `GET /auth/callback`, `POST /auth/logout`, `POST /auth/switch-tenant` (Keycloak token exchange; clears caches client-side).

## 2. Conventions

| Concern | Rule |
| --- | --- |
| Versioning | URL major (`/v1`); `api_version` date in events (`2026-09-01`); additive changes only within a version; oasdiff breaking check in CI |
| Media type | `application/json`; errors `application/problem+json`; SSE `text/event-stream` |
| Naming | snake_case JSON fields; plural resource nouns; actions as `POST /resource/{id}/<verb>` |
| IDs | Opaque prefixed strings (`cus_`, `sub_`, `inv_`, `pay_`, `evt_`, `whe_`, `key_`); UUIDv7 internally |
| Money | `{"amount": <int64 minor units>, "currency": "<iso lowercase>"}`; never floats |
| Time | RFC 3339 UTC timestamps; dates `YYYY-MM-DD` |
| Idempotency | `Idempotency-Key` REQUIRED on creating/money-moving POSTs (marked in spec); 24 h replay; different body with same key → 422 |
| Concurrency | `ETag` on reads; `If-Match` REQUIRED on PATCH of versioned resources → 412 on mismatch |
| Pagination | `limit` (1–100, default 50), `starting_after`; response `{data, has_more, next_cursor}` |
| Filtering | explicit query params per endpoint (`status`, `q`, `created[gte]`) |
| Tracing | `traceparent` accepted and returned; `Request-Id` response header on every response |
| Actor/audit | tenant API: actor from token; ops API: `X-Access-Reason` REQUIRED on tenant-data reads and writes |
| Rate limits | `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`; 429 + `Retry-After` |
| Sensitive data | never returned: API key secrets (except once), webhook secrets (except once), card numbers; contact PII masked in ops API unless `reveal=true` |

## 3. Error model

```json
{"type": "https://docs.tally.example/problems/idempotency-key-reused", "title": "Idempotency key reused with a different request",
 "status": 422, "code": "IDEMPOTENCY_KEY_REUSED", "detail": "Key a1b2… was first used for POST /v1/payments with another body.",
 "param": "Idempotency-Key", "request_id": "req_7Hc2…"}
```

| code | status | When |
| --- | --- | --- |
| VALIDATION_FAILED | 400 | schema or field validation; `param` names the field |
| UNAUTHENTICATED | 401 | missing/invalid/revoked credential |
| FORBIDDEN_SCOPE | 403 | key lacks scope; role lacks permission |
| NOT_FOUND | 404 | unknown id **or another tenant's id** (never 403, to avoid existence leaks) |
| INVALID_STATE | 409 | illegal transition (finalize a VOID invoice, archive a price in use) |
| PRECONDITION_FAILED | 412 | If-Match mismatch |
| IDEMPOTENCY_KEY_REUSED | 422 | same key, different request hash |
| IDEMPOTENCY_IN_PROGRESS | 409 | same key still executing |
| RATE_LIMITED | 429 | plan limit exceeded |
| TENANT_SUSPENDED | 423 | writes on a suspended tenant |
| APPROVAL_REQUIRED | 202 (not an error) | ops action queued for four-eyes |
| STEP_UP_REQUIRED | 401 | ops approve without fresh WebAuthn |
| INTERNAL | 500 | unexpected; body has only `request_id` |

Business outcomes are **not** HTTP errors: a declined card is `201` with `status: FAILED`; a dunning step is a state change.

## 5. Realtime (SSE)

`GET /v1/streams/webhook_deliveries` and `GET /ops/v1/streams/health`. Envelope per message: `event: <type>`, `id: <monotonic cursor>`, `data: <JSON>`. Types: `delivery.created`, `delivery.updated`, `endpoint.health`, `heartbeat` (every 15 s). Clients reconnect with `Last-Event-ID`; the server replays up to 5 minutes. One connection per tab (NFR-RT-01); the web client batches updates per animation frame.

## 7. Async events

| Topic | Key | Producer → consumer | Schemas |
| --- | --- | --- | --- |
| `tally.billing.events.v1` | tenant_id | core outbox → dispatcher, core reporting | invoice, payment, subscription, customer |
| `tally.usage.raw.v1` | tenant_id | core outbox → aggregator | usage-raw |
| `tally.usage.rollups.v1` | tenant_id | aggregator → core metering | usage-rollup |
| `tally.webhooks.control.v1` | tenant_id | core ↔ dispatcher | webhook-control |
| `tally.usage.agg-state.v1` (compacted) | window key | aggregator internal | — |

Headers on every record: `event-type`, `tenant-id`, `schema-version`, `traceparent`. Partitions: 24 per topic locally. Retention: 7 days (billing, usage raw), 30 days (rollups), compacted (control, agg-state). Consumers dedupe on envelope `id`.

## 8. Parallel development workflow

1. Day 1 of the sprint: tech lead opens one `contract/<slice>-<slug>` PR per slice (edits `scripts/gen_openapi.py` tables / event generator, runs `make contracts`).
2. CI: Spectral lint, oasdiff breaking diff, JSON Schema compile, webhook vectors self-check.
3. After merge, `make gen`: core gets new Spring interfaces (unimplemented = compile error), workers get types, web/ops-web get typed clients + MSW handlers.
4. Providers validate real responses against the spec in integration tests; consumers test on mocks from the same spec.
5. Integration checkpoint: `make up FLAGS=<flag>=true`, mocks off, slice journey in `make e2e` green, then flag on.
