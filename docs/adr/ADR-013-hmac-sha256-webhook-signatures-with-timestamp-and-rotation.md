# ADR-013: HMAC-SHA256 webhook signatures with timestamp and rotation

- **Status:** Accepted
- **Date:** 2026-09-22
- **Deciders:** Tech lead (Phan Cao Khai)
- **Related:** FR-WH-02, FR-WH-03, TLY-305, TLY-312

## Context
Receivers must verify origin and freshness; secrets must rotate without downtime.

## Options considered
1. Asymmetric signatures — no shared secret / heavier for receivers
2. HMAC over timestamp + raw body with multiple v1 values during overlap — common, simple

## Decision
`Tally-Signature: t=<ts>,v1=<hex>[,v1=…]`, 300 s tolerance, 24 h rotation overlap; golden vectors generated by script are normative (docs/03 §4).

## Consequences
Easy receiver implementation; replay protection depends on receivers checking t; changes require new vectors first.
