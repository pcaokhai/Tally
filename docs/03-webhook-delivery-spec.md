# Webhook Delivery Interface Specification

Version 1.0 · 2026-09-22 · Owner: Tech lead · Normative source: `contracts/webhooks/signature-vectors.json`, `contracts/events/*.schema.json`

This is the wire contract between Tally's dispatcher and tenant endpoints, and the rule set both sides must implement. RFC 2119 words apply.

## 1. Transport

- HTTPS only (TLS 1.2+); plain HTTP is rejected at registration except in test mode against `localhost` tunnels.
- One event per request: `POST <endpoint url>`, `Content-Type: application/json; charset=utf-8`.
- Maximum body 256 KB; events larger than that MUST carry a reference instead of the object.
- Connect timeout 3 s; total attempt timeout 10 s. Redirects are NOT followed.
- The dispatcher MUST resolve DNS and check the resolved IP **at dial time** against the blocklist (loopback, RFC 1918, link-local incl. `169.254.169.254`, CGNAT, IPv6 ULA/link-local, multicast). A blocked IP fails the attempt with `SSRF_BLOCKED` (FR-WH-07, NFR-SEC-06).

## 2. Encoding

The body is the event envelope from `contracts/events/*.schema.json` serialized as compact JSON (no insignificant whitespace), UTF-8. Money is integer minor units. Unknown fields MUST be ignored by receivers; new fields are additive within an `api_version`.

| `Tally-Attempt` | `3` | 1-based |
| `User-Agent` | `Tally-Webhooks/1.0` | |
| `traceparent` | W3C | Continues the originating trace |

## 4. Signature

- `v1 = hex(HMAC_SHA256(key = UTF-8 bytes of the endpoint secret, message = "<t>.<raw body bytes>"))`.
- During rotation (FR-WH-03) the dispatcher MUST sign with every secret whose `expires_at` is in the future and emit one `v1=` per secret. Overlap default: 24 h.
- Receivers MUST verify against the **raw bytes** received (never re-serialized JSON), MUST use constant-time comparison, and MUST reject when `|now − t| > 300 s`.
- Golden vectors: `contracts/webhooks/signature-vectors.json` (basic, rotation overlap, stale timestamp, tampered body, whitespace change). Rule: **any change to signing ⇒ new vector first**, generated by `scripts/gen_webhook_vectors.py`; the Go signer test runs every vector.

## 6. Delivery semantics

- **At-least-once.** Receivers MUST be idempotent on `Tally-Event-Id`.
- **Ordering** is best-effort per tenant (Kafka key = tenant id); receivers MUST NOT rely on order across event types and SHOULD use `created_at` plus object state.
- Success = any 2xx within the timeout. 410 Gone disables the endpoint immediately. Any other status, timeout or network error is a failure.

## 7. Retry, circuit and disable rules

| Rule | Value |
| --- | --- |
| Retry schedule after failure | 30 s, 2 m, 8 m, 30 m, 2 h, 6 h, 12 h, 24 h, each with full jitter (0–100 %) |
| Max attempts / max age | 8 retries / 72 h, then **DEAD_LETTERED** |
| Circuit opens | 10 consecutive failures on the endpoint → new messages **HELD**, probe every 60 s |
| Auto-disable | 50 consecutive failures → endpoint DISABLED, event `webhook_endpoint.auto_disabled`, tenant emailed |
| Re-enable | test event first; on 2xx, HELD messages drain at ≤ 20/s |
| Replay | creates a new delivery message with `replay_of`; same `event.id` |
| Fairness | per-tenant queues, weighted round-robin; ≤ 8 in-flight per endpoint, 256 total |

## 8. Result classification

| Outcome | Classified as | Next |
| --- | --- | --- |
| 2xx | DELIVERED | done |
| 410 | FAILED + disable | endpoint DISABLED |
| 408, 429, 5xx, timeout, connection error | FAILED (retryable) | schedule retry; `Retry-After` honored up to 1 h |
| other 4xx | FAILED (retryable, counts to disable) | schedule retry |
| SSRF_BLOCKED | FAILED (non-retryable) | endpoint DISABLED with reason |

## 9. Timers

| Timer | Value |
| --- | --- |
| Connect / total attempt | 3 s / 10 s |
| Signature tolerance | 300 s |
| Secret overlap on rotation | 24 h |
| Circuit probe interval | 60 s |
| Delivery message retention | 30 days (DEAD_LETTERED: 90 days) |

## 10. Tracing

The dispatcher continues the `traceparent` from the Kafka header, creates a span per attempt (`webhook.attempt`, attributes `tenant.id`, `endpoint.id`, `event.id`, `http.status_code`, `attempt`) and sends `traceparent` to the endpoint.

## 11. Security

Secrets are generated with 256 bits of entropy, stored encrypted with the tenant DEK (core) and delivered to the dispatcher only inside `webhook_endpoint.updated` control events encrypted with the dispatcher's public key; the dispatcher keeps them in memory and in its projection encrypted at rest.

## 12. Change control

Any change here is a contract change: `contract/<slice>-<slug>` PR, vectors regenerated, `api_version` bumped for breaking payload changes, ADR if semantics change (ADR-012, ADR-013).
